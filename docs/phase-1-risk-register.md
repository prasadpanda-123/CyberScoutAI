# CyberScout AI — Phase 1 Risk Register

The following risk register tracks security, data integrity, authentication, and architectural risks identified during Phase 0 and addressed or tracked during Phase 1. All findings and evidence are sourced directly from the active CyberScout AI codebase.

| ID | Risk | Severity | Evidence | Mitigation | Status |
| :--- | :--- | :---: | :--- | :--- | :---: |
| **RSK-01** | **Dropped Administrator Audit Trail** | **Critical** | `src/database/audit_log_repository.py:38-57`: Calling `uuid.UUID(str(user_id))` on integer admin IDs threw `ValueError`, silently setting `safe_user_id = None`. All admin actions lacked traceable user IDs in `AuditLogs`. | Updated `log_event()` to resolve integer IDs against `Admins` table, verify `username`, keep `user_id = None` to satisfy `fk_auditlogs_user_id` FK to `Users`, and record `[admin_id: X]` in `details`. | **RESOLVED** |
| **RSK-02** | **Hardcoded Seeded Default Credentials in Production** | **Critical** | `src/database/seed.py:92`: `SeedManager.seed_users()` seeded `admin@cyberscout.ai` with default password `Admin@CyberScout2026!` at every database connection initialization. | Updated `seed_users()` to detect production environment and skip default credential creation unless `CYBERSCOUT_INITIAL_ADMIN_PASSWORD` is supplied; forces first-run setup via `/setup`. | **RESOLVED** |
| **RSK-03** | **Unauthenticated CSRF Bypass on User Registration** | **High** | `dashboard/routes/auth.py:154-177`: `POST /register` accepted student registrations without extracting or checking CSRF tokens. | Added `@auth_bp.before_request` hook, rendered `csrf_token` in `register.html`, and enforced `AdminSecurityManager.verify_csrf_token()` validation with HTTP 400 rejection. | **RESOLVED** |
| **RSK-04** | **Unauthenticated CSRF Bypass on First-Run Setup** | **High** | `dashboard/routes/auth.py:26-53` and `dashboard/templates/setup.html:53`: `/setup` accepted credentials without CSRF tokens; template lacked hidden CSRF field. | Injected hidden `csrf_token` input into `setup.html`; enforced constant-time token verification on `POST /setup`. | **RESOLVED** |
| **RSK-05** | **CSRF Bypass on Password Reset Requests** | **High** | `dashboard/routes/auth.py:198-202`: `POST /forgot-password` processed requests without checking CSRF tokens. | Added server-side CSRF validation in `forgot_password()` handler, rejecting invalid/missing tokens with HTTP 400. | **RESOLVED** |
| **RSK-06** | **CSRF Token Bypass on Login Route** | **High** | `dashboard/routes/auth.py:80`: `if session_csrf and csrf_token and not secrets.compare_digest(...)` skipped verification when `csrf_token` was omitted by callers. | Restructured validation to fail closed in production when CSRF token is missing or invalid. | **RESOLVED** |
| **RSK-07** | **Weak Password Complexity on First-Run Setup** | **Medium** | `dashboard/routes/auth.py:36`: Initial setup only checked `len(password) < 10` without checking uppercase, lowercase, digit, or special characters. | Enforced `AdminSecurityManager.validate_password_strength()` rules (10+ chars, uppercase, lowercase, digit, special character) on `/setup`. | **RESOLVED** |
| **RSK-08** | **Setup Route Abuse / Brute Force** | **Medium** | `dashboard/routes/auth.py:18-54`: `/setup` lacked rate limiting or setup secret verification before account creation. | Integrated `AdminSecurityManager.is_locked_out()` rate limiting (5 attempts/15 min) and optional `CYBERSCOUT_SETUP_KEY` verification. | **RESOLVED** |
| **RSK-09** | **UUID Type Mismatch in User Creation** | **Medium** | `src/database/user_repository.py:92`: `create_user()` returned raw `uuid.UUID` object from `RETURNING id`, conflicting with `str` UUID in `get_by_id()` and sessions. | Normalized `create_user()` to return canonical string representation `str(row[0])`. | **RESOLVED** |
| **RSK-10** | **App Factory Dict Config Silently Ignored** | **Low** | `dashboard/app.py:46`: `app.config.from_object(config_class)` silently ignored dictionary configs, causing `TESTING=True` to be dropped. | Added `isinstance(config_class, dict)` branch using `app.config.from_mapping(config_class)`. | **RESOLVED** |
| **RSK-11** | **Permissive PostgreSQL Row Level Security (RLS)** | **High** | `src/database/connection.py:355-360`: Tables have RLS enabled with `USING (true) WITH CHECK (true)`, offering zero tenant isolation at DB layer. | Scheduled for Phase 2: Implement session context variables (`SET LOCAL app.current_user_id`) in SQLAlchemy connection manager. | **TRACKED (Phase 2)** |
| **RSK-12** | **Dual Entity Maintenance Overhead (`Admins` vs. `Users`)** | **Medium** | `src/database/models/admin.py` vs. `src/database/models/user.py`: Separate tables require maintaining dual repositories and distinct session keys. | Preserved in Phase 1 to prevent breaking active RBAC and boundary test suites; scheduled for unified identity consolidation in Phase 2. | **TRACKED (Phase 2)** |
| **RSK-13** | **Unimplemented Password Reset Dispatch** | **Medium** | `dashboard/routes/auth.py:198-202`: `forgot_password()` flashed confirmation but did not generate reset tokens or transmit emails. | CSRF and audit tracking secured in Phase 1; cryptographic token generation and Brevo email dispatch scheduled for Phase 4. | **TRACKED (Phase 4)** |
