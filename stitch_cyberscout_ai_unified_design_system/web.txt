ADMINISTRATOR PORTAL ROUTES (/admin/*)

25. Route: GET /admin/login, POST /admin/login
    Blueprint: admin_ui
    Function: admin_login()
    Template: admin/admin_login.html
    Auth Required: No (Pre-auth stage)
    Form Fields: admin_username, admin_password, csrf_token, next
    Security: 15-minute lockout on 5 consecutive failures; generates 6-digit OTP code, stores server-side state in memory, sends email, sets session["admin_pending_token"], redirects to /admin/verify-otp.

26. Route: GET /admin/verify-otp, POST /admin/verify-otp
    Blueprint: admin_ui
    Function: admin_verify_otp()
    Template: admin/admin_verify_otp.html
    Auth Required: Pending Token (session['admin_pending_token'])
    Form Fields: otp_code, csrf_token
    Security: Validates 5-minute expiration; max 5 attempts; hashes OTP code with SHA-256 and verifies constant-time (secrets.compare_digest); on success establishes session["admin_authenticated"] = True, sets admin_user_id, admin_username, admin_role, admin_csrf_token.

27. Route: GET /admin/logout
    Blueprint: admin_ui
    Function: admin_logout()

     * csrf_token: Hex string (32 bytes)
     * current_user: {"id", "username", "role", "is_authenticated"}
     * current_admin: {"id", "username", "role", "is_authenticated", "csrf_token"}
   - Inline Scripts: LocalStorage theme reader, sidebar collapse state toggle.

   - Extends: None (Root HTML document with isolated red/dark theme)
   - Includes: None (Self-contained navbar, offcanvas, alerts, and footer)
   - Blocks: title, extra_head, content, extra_scripts
   - Dynamic Navigation: Highlights active_page (admin_dashboard, admin_collectors, admin_scheduler, admin_logs, admin_users, admin_configuration, admin_diagnostics).

3. dashboard.html
   - Extends: base.html

6. AUTHENTICATION & MFA STATE MACHINES
================================================================================

--------------------------------------------------------------------------------
USER AUTHENTICATION FLOW
--------------------------------------------------------------------------------
1. User submits credentials to POST /login (identifier, password, csrf_token, next).
2. Server validates CSRF token.
3. Server looks up user by username or email in Users table.
4. Server verifies password hash.
5. If user has an Admin role ("Admin", "Super Admin", "Administrator"), login is rejected with a warning and redirected to /admin/login (Portal Isolation).
6. If valid student/analyst user:
   - Clears existing session (session.clear() for Session Fixation Defense).
   - Sets session["user_id"] = user.id
   - Sets session["username"] = user.username
   - Sets session["email"] = user.email
   - Sets session["role"] = user.role
   - Sets session["user_csrf_token"] = secrets.token_hex(32)
   - Logs AuditLog event: AUTH / USER_LOGIN / SUCCESS
   - Redirects to safe next_url or /dashboard.

--------------------------------------------------------------------------------
ADMINISTRATOR MFA AUTHENTICATION FLOW
--------------------------------------------------------------------------------
1. Administrator submits credentials to POST /admin/login (admin_username, admin_password, csrf_token, next).
2. Server validates CSRF token.
3. Server checks rate limiting and account lockout (max 5 failed attempts in 15 minutes per IP + username).
4. Server authenticates administrator against Admins table (falls back to Users table if role is Admin).
5. If invalid credentials, records failure, logs AUTH / ADMIN_LOGIN / FAILED, and flashes error.
6. If password verified:
   - Generates cryptographically secure 6-digit numeric OTP code (e.g. "847291").
   - Computes SHA-256 hash of OTP code.
   - Stores pending MFA state in server memory (_pending_mfa_sessions dict):
     {user_id, username, email, role, otp_hash, expires_at (+300s), attempts: 0, next_url}
   - Generates opaque random hex pending_token (prevents OTP hash leaking into client cookies).
   - Sets session["admin_pending_token"] = pending_token.
   - Dispatches OTP code via EmailSender to the admin's email.
   - Logs AuditLog event: MFA / OTP_GENERATED / SUCCESS.
   - Redirects to GET /admin/verify-otp.
7. Admin enters 6-digit code at POST /admin/verify-otp.
8. Server checks 5-minute expiration window (expires_at).
9. Server increments attempt counter (locks out if > 5 attempts).
10. Server verifies submitted OTP against stored SHA-256 hash using secrets.compare_digest().
11. On success:
    - Clears pending MFA state from memory.
    - Resets failed attempt counter.
    - Clears session dictionary (session.clear()).
    - Sets session["admin_authenticated"] = True
    - Sets session["admin_user_id"] = user_id
    - Sets session["admin_username"] = username
    - Sets session["admin_role"] = role
    - Sets session["admin_csrf_token"] = secrets.token_hex(32)
    - Logs AuditLog event: MFA / OTP_VERIFIED / SUCCESS
    - Logs AuditLog event: AUTH / ADMIN_LOGIN / SUCCESS
    - Redirects to next_url or /admin/dashboard.

9. SECURITY BOUNDARIES, HEADERS, CSRF & CLIENT IP RESOLUTION
================================================================================

1. OWASP Security Headers (dashboard/app.py after_request):
   - X-Content-Type-Options: nosniff
   - X-Frame-Options: DENY
   - Referrer-Policy: strict-origin-when-cross-origin
   - Permissions-Policy: geolocation=(), camera=(), microphone=()
   - Strict-Transport-Security: max-age=31536000; includeSubDomains
   - Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net; style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com https://cdn.jsdelivr.net; img-src 'self' data:; connect-src 'self' https://cdn.jsdelivr.net;
   - Anti-Caching: Cache-Control: no-store, no-cache, must-revalidate, max-age=0, private on dynamic routes.
   - Version Disclosure Removal: Server and X-Powered-By headers stripped.

2. Session Cookie Hardening:
   - Cookie Name: cyberscout_session
   - HttpOnly: True
   - SameSite: Lax
   - Secure: True (production/non-debug)
   - Lifetime: 1 day (PERMANENT_SESSION_LIFETIME = timedelta(days=1))

3. CSRF Protection:
   - Globally generated and injected into Jinja template context as {{ csrf_token }}.
   - Validated server-side on POST /login, POST /register, POST /profile, POST /admin/login, POST /admin/verify-otp, POST /admin/users.

4. Client IP Resolution (RFC 7239 / src/utils/ip_utils.py):
   - Respects TRUSTED_PROXY_COUNT environment setting.
   - When 0 (direct connection): Returns request.remote_addr only (prevents header spoofing).
   - When > 0 (behind reverse proxies like Cloudflare/Render): Safely parses CF-Connecting-IP, X-Real-IP, X-Forwarded-For, Forwarded.
   - Strips ports, normalizes IPv6/IPv4-mapped IPv6, falls back safely to '127.0.0.1'.

4. Must preserve all 11 Admin Action API endpoints under /admin/api/*.
5. Must preserve CSRF token hidden inputs and session fixation security flows.
6. Must preserve isolated boundary between User Portal and Administrator Portal (/admin/*).

DESIGN FREEDOM (Can be completely redesigned):
1. Visual styling, fonts, typography scale, modern cyber aesthetics.
2. Layout structure, cards, table layouts, filters, search toolbar.
3. Mobile responsive navigation, floating action bars, command menus.
4. Micro-interactions, skeleton loaders, and interactive chart components.
